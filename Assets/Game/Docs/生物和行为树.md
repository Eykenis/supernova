# 生物行为状态

当前 monster 使用 CreatureBehaviorAgent 状态机：

- Idle：停止通用物理 Motor。
- Wander：在附近随机采样一个可站立节点，寻路并沿路径移动。
- Pursue：以玩家脚部所在节点为目标寻路并移动。
- Attack：玩家已经处于攻击距离内时执行近战攻击。
- Hurt：短暂受击状态。
- Dead：停止行为、移除物理组件并延迟销毁。
- Caught：被磁吸装置持有时停止自主行为。

状态选择使用 monster 与玩家之间的体素距离：模拟范围外进入 Idle，追击范围内选择
Pursue，近身时选择 Attack，其余模拟范围内选择 Wander。离开 Wander/Pursue 时会丢弃
当前路径，重新进入移动状态后按当前地形重新规划。

## 寻路

导航实现位于 `Assets/Game/Runtime/Creatures/Navigation/`，分层参照
`Assets/Game/Docs/Minecraft寻路.md` 总结的 Minecraft 结构。核心是纯 C#，不引用
MonoBehaviour，便于 EditMode 测试直接驱动。

| 类型 | 职责 |
| --- | --- |
| `IVoxelSolidityQuery` / `VoxelTerrainSolidityQuery` | 体素实心查询。查询失败表示区块未生成，按不可通行处理，不当作空气。 |
| `CreatureBodyBox` | 生物包围盒，换算为整数体素，宽度强制为奇数使其居中于脚部列。 |
| `PathNodeType` | 只有 `Walkable` 与 `Open`；不可进入通过分类失败表达。 |
| `VoxelPathNodeMaker` | 按需生成隐式图：节点分类、包围盒净空、八方向后继、抬升与下落解析、对角防穿墙角。 |
| `PathNodeMinHeap` | 带 decrease-key 的二叉最小堆。 |
| `VoxelPathfinder` | A* 搜索，含访问上限与最近点回退。 |
| `VoxelPath` | 节点序列、当前索引、是否真正抵达目标。 |
| `CreatureNavigator` | 持有当前路径、决定何时重算、Wander 目标采样、推进节点。 |
| `CreaturePhysicsMotor` | 水平速度、转向与一次性跳跃冲量；竖直运动始终由重力和碰撞决定。 |

### 图是邻接关系，不是高度场

节点表示脚部位置。可站立判据为：中心列下方体素实心，且包围盒覆盖的体素全部为已生成
的空气。支撑只看中心列——若要求包围盒每一列下方都有地面，斜坡、洞缘和台阶边都会被
误判为不可站立。

**包围盒尺寸不能照抄 Minecraft 的 `floor(尺寸 + 1)`。** Minecraft 一个体素就是一整个方块，
生物不会远小于一格；本项目体素 0.42 只是生物的一小部分，那个公式会把 0.68m 宽的骷髅膨胀成
3 格宽（1.26m）× 5 格高（2.10m）的空腔要求 —— 洞穴里几乎不存在，导致**所有节点分类失败、
根本规划不出路径**（表现为怪物面朝玩家但完全不动）。

因此宽度改为：≤ 2 格宽的生物按**单列**规划，侧向余量交给物理（刚体擦到墙会自然滑开，真卡住
有看门狗兜底）；只有确实宽大的生物（如 Skeleton Giant，4.29 格）才检查邻列。高度仍做实际
校验（四舍五入取整），避免把生物规划到钻不进去的矮洞。骷髅由此从 45 次体素探测降到 4 次。

边只关心两节点的整数层差：0 为平走，`+1..最大跳跃高度` 为抬升，`-1..最大安全落差`
为下落。因此 Marching Cubes 平滑相接的地面在图上就是同层邻居，其真实的微小高度差交由
物理运动完成，不需要图去描述绝对高度。

对角移动要求组成该方向的两个正交邻居都可进入，避免从两个墙体之间斜穿。

### 代价与启发式

单步代价与启发式都使用三维直线距离，因此启发式一致、A* 保持最优，对角一步的代价恰为
根号二。抬升与下落不额外加权，其取舍已由层差上限表达。

### 访问上限与最近点

搜索维护一个「最近点」：到目标直线距离最小的已访问节点，平局取累计代价更小者。它在计算
启发式的同处以单变量增量更新，因此取用是 O(1)，无需扫描。展开数达到上限时，直接回溯该
节点得到部分路径（`ReachesTarget` 为 false），生物会走向最接近目标的可达位置，而不是原地
不动。目标被完全封闭时同样如此。

### 重算时机

追击不会每帧重算。`CreatureNavigator` 使用一个随机化冷却区间（避免同帧集中搜索），并要求
目标位移超过阈值才提前重算；腾空期间不重算，以免在跳跃中途重采样脚部节点而丢弃仍在执行
的路径。Wander 只在没有活动路径时挑选新目标，连续采样失败会进入一段停顿再重试。

### 跳跃只在真正需要时触发

层差不超过 `StepUpHeight`（默认 1 层）的上升视为可直接走过，不请求跳跃。原因是本项目
体素（0.42）远小于生物（高 1.66），Marching Cubes 的插值斜面被整数量化后，视觉上完全
平坦的地面也会产生大量 `y, y, y+1, y…` 交替层；这些坎由碰撞体自然跨过即可。只有超过该
高度的上升才交给 JumpControl。

同一条爬升边只发一次跳跃：命令 id 由目标节点坐标派生（而非每帧自增计数器），Motor 以
`commandId` 去重并要求接地，因此重复请求不会在腾空中叠加第二次起跳。

### 卡住恢复

整数层差模型仍可能漏掉个别真实障碍。因此带一个看门狗：`StuckCheckInterval` 秒内若在有移动
指令且已接地的前提下，实测速度持续低于指令速度的 `StuckSpeedFraction`，先尝试跳跃；连续尝试
超过上限则丢弃路径重新规划。该间隔逐 prefab 可调，下界 0.01 秒：调长可避免把正常转向、拥挤和
斜坡接触误判为卡住，调短则恢复更灵敏但容易误跳。

两个要点：
- **速度度量必须统一**。判据用 `motor.CommandedSpeedFraction`（实测速度 ÷ **本次指令**
  速度），不能用 `NormalizedHorizontalSpeed` —— 后者除的是 `animationReferenceSpeed`，
  那是给动画用的表现值，与导航指令速度无关（满速行走时只有 0.8，永远到不了 1）。
- **不能用「到下一节点的距离是否缩小」推断进展**。重算会更换 `nextNode`、节点推进会让
  距离突增，两者都会在平地上造成误判。

起点解析另有兜底：物理占有生物的真实位置，采样出的脚部节点若不被整数模型接受，会在附近
若干格内吸附到可站立节点。该容差只作用于起点解析，不会进入后继生成。

### 调参

`CreatureNavigationProfile` 序列化在 Agent 上，逐 prefab 配置最大跳跃高度、最大安全落差、
访问上限、移动速度与加速度、重算间隔与目标位移阈值、Wander 采样范围、卡住恢复参数。
生成投放相关参数仍留在 `MonsterSpawnDefinition`。

选中运行中的 monster 时，Scene 视图会显示当前状态颜色、追击范围、当前路径折线与下一节点；
完整路径为绿色，部分路径为橙色。Inspector 中的 `Last Visited Node Count` 可用于区分
「重算抖动」（每帧变化）与「路径稳定但不移动」（容差或接地检测问题）。
