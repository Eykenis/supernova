# Minecraft 寻路机制调查总结

> 调研范围：Minecraft Java Edition 1.21.x 的普通地面生物寻路。类名采用 Yarn 1.21.8 映射；不同版本的字段和方法名可能变化，但整体分层和核心算法长期稳定。

## 1. 核心结论

Minecraft 不会预先为整个世界生成完整导航图，也不会把所有三维空气体素都加入搜索。

寻路开始后，节点生成器按需检查附近方块，动态生成 PathNode(x, y, z)。节点代表“生物脚部可以到达的位置”，并带有地形类型与寻路代价。

普通地面生物的寻路可以概括为：

- 节点使用三维坐标；
- 可达节点主要分布在地形表面；
- 上台阶、跳跃和下落通过不同高度节点之间的连接表达；
- A* 规划落脚点序列，不计算逐帧跳跃抛物线；
- 移动控制和实体物理负责行走、起跳、腾空与落地；
- 追击玩家时不会每 tick 执行完整 A*，而是按目标移动和倒计时重算路径。

所以，地面生物使用的是一张带高度变化的隐式表面图，也可以称为 2.5D 图。飞行和水生生物使用其他节点生成器，才更接近三维体积寻路。

## 2. 系统分层

~~~mermaid
flowchart TD
    A["目标选择 Target Goal"] --> B["追击或攻击 Goal"]
    B --> C["EntityNavigation / MobNavigation"]
    C --> D["LandPathNodeMaker：生成候选节点"]
    D --> E["PathNodeNavigator：A* 搜索"]
    E --> F["Path：落脚节点序列"]
    F --> G["Navigation：逐节点跟随"]
    G --> H["MoveControl：转向和移动"]
    H --> I["JumpControl：触发跳跃"]
    I --> J["实体碰撞、速度和重力"]
~~~

### 2.1 Goal：决定为什么移动

Goal 系统选择生物当前行为，例如游荡、追击、逃离危险、移动到指定位置或近战攻击。目标选择 Goal 找到玩家等目标，攻击 Goal 再向导航系统请求路径。

Goal 通常不直接展开 A* 节点，也不负责方块碰撞。

### 2.2 Navigation：管理路径

EntityNavigation 及其地面实现 MobNavigation 负责：

- 请求到坐标、方块或实体的路径；
- 保存并推进当前 Path；
- 判断下一节点是否到达；
- 设置移动速度；
- 检测超时和长期无进展；
- 在目标或环境变化后重算；
- 停止失效或已完成的路径。

### 2.3 PathNodeMaker：把世界转换成节点

普通地面生物主要使用 LandPathNodeMaker。它根据世界方块、碰撞形状、生物包围盒、步高、安全下落距离、特殊通行能力及地形代价，动态生成当前节点的合法后继。

### 2.4 PathNodeNavigator：执行 A*

PathNodeNavigator 使用优先队列，在 PathNodeMaker 提供的隐式图上搜索路径。它只负责找到代价较低的节点序列，不负责给实体施加速度。

### 2.5 MoveControl 与 JumpControl：执行路径

Navigation 把下一节点交给 MoveControl。移动控制器调整朝向和前进速度，并在需要抬升或越过障碍时激活 JumpControl。

JumpControl 只产生短暂的跳跃意图。竖直速度、重力、碰撞和落地由实体运动系统处理。

## 3. 如何判断一个位置能否站立

### 3.1 节点代表脚部位置

PathNode(x, y, z) 更接近“实体脚部能够放置在这里”，并不只是某个实心方块。

候选位置通常需要满足：

1. 下方存在可接受的支撑；
2. 生物身体占用空间足够；
3. 生物包围盒不会与方块碰撞形状相交；
4. 所覆盖方块的节点类型允许进入；
5. 生物对节点类型的寻路代价不是禁止值；
6. 从来源节点到候选节点的高度变化合法。

下面这种判断不足以完整模拟 Minecraft：

~~~text
脚下是实心方块
脚部是空气
头部是空气
~~~

它没有考虑实体宽度、非完整方块碰撞形状、危险地形、门、栅栏、液体和过渡碰撞。

### 3.2 生物尺寸参与检查

节点生成器会按照生物包围盒检查多个方块：

- 高个生物需要更高净空；
- 宽体型生物需要检查中心列周围空间；
- 窄通道可能允许小型生物通过，却拒绝大型生物；
- 只检查脚下一列会产生穿墙或卡住路径。

### 3.3 碰撞形状决定真实表面

半砖、楼梯、雪层、栅栏、活板门和地毯等方块并非完整立方体。它们的可站立表面高度和阻挡范围不同。

节点高度与过渡检查需要参考实际碰撞形状，不能永远使用方块顶面的整数高度。

### 3.4 PathNodeType

LandPathNodeMaker 会把局部环境分类成 PathNodeType。常见类型包括：

- WALKABLE：普通可行走位置；
- OPEN：开放空间，可能需要继续向下寻找支撑；
- BLOCKED：不可通过；
- FENCE：栅栏类阻挡；
- WATER、WATER_BORDER：水及水边；
- LAVA：岩浆；
- DOOR_OPEN、DOOR_WOOD_CLOSED、DOOR_IRON_CLOSED：不同门状态；
- RAIL、UNPASSABLE_RAIL：铁轨相关位置；
- DANGER_FIRE、DAMAGE_FIRE：火焰危险或伤害区域；
- DANGER_OTHER、DAMAGE_OTHER：其他危险区域；
- POWDER_SNOW、DANGER_POWDER_SNOW：细雪相关位置。

每种类型有默认寻路代价，具体生物还可覆盖自己的代价。

- 负代价通常表示拒绝进入；
- 较高代价表示可以进入，但 A* 倾向绕行；
- 同一环境对不同生物可能有不同结果；
- 开门、进门、游泳等能力也会影响节点生成。

### 3.5 可站立条件总结

~~~text
可站立节点
= 有合法支撑
+ 实际表面高度可用
+ 完整包围盒有净空
+ 节点类型可接受
+ 从来源节点能够合法到达
~~~

一个位置本身能够站立，不代表能从当前方向和高度到达。

## 4. 三维节点图如何生成

### 4.1 隐式图

Minecraft 不会先枚举世界中所有节点和边。A* 展开某个节点时，LandPathNodeMaker 才计算附近的候选后继。

这种方式只检查本次搜索实际接触的区域，无需长期保存整个世界的导航图。方块变化能在下一次搜索中反映，但每次搜索会重复进行方块类型和碰撞查询。

### 4.2 水平邻居

节点生成器首先尝试东、西、南、北四个水平方向。每个候选都会检查：

- 脚部位置的节点类型；
- 支撑或开放状态；
- 实体净空；
- 与当前节点的高度差；
- 过渡包围盒碰撞；
- 节点代价。

### 4.3 对角邻居

对角移动不能只检查终点，否则实体可能从两个相邻墙体之间斜穿过去。

节点生成器会参考组成对角方向的两个正交邻居。只有侧边通行条件满足时，才允许添加对角后继。

### 4.4 高度变化

候选位置与当前节点高度不同时，节点生成器会尝试：

- 在允许步高内进入稍高节点；
- 寻找可以跳上的高处落脚节点；
- 从开放位置向下寻找安全落点；
- 拒绝过高墙体、过深坑洞或净空不足的过渡。

图中可能出现：

~~~text
(10, 64, 8) -> (11, 65, 8)   向上
(11, 65, 8) -> (12, 62, 8)   向下
~~~

节点坐标是三维的，但边始终对应地面生物能够执行的移动。

## 5. A* 如何选择路径

搜索评分可以概念化为：

~~~text
f(n) = g(n) + h(n) + 节点附加代价
~~~

- g(n)：从起点到当前节点的累计成本；
- h(n)：到目标的启发式估计；
- 节点附加代价：水、火焰、危险方块或生物偏好等。

搜索还会受到跟随范围、节点访问上限和目标容差等约束。

目标无法完全到达时，寻路可能返回接近目标的部分路径。怪物可以走到墙边、悬崖边或离目标最近的可达节点，而不是一定原地不动。

## 6. 跳跃如何处理

### 6.1 规划阶段不计算抛物线

普通地面寻路通常不会生成完整空中节点链，而是直接表达：

~~~text
较低落脚节点 -> 较高落脚节点
~~~

A* 判断较高落脚点是否可达，实体运动系统负责中间的腾空过程。

### 6.2 寻找较高节点

当水平邻居在当前脚高不可通过时，LandPathNodeMaker 会在允许向上步幅内尝试高处节点，检查：

1. 高处是否有合法支撑；
2. 高处是否能容纳完整生物；
3. 障碍高度是否允许；
4. 起跳方向和过渡空间是否碰撞；
5. 高处节点类型和代价是否可接受。

合法时，高处节点成为当前节点的后继并参与 A*。

### 6.3 执行阶段

~~~text
路径下一节点更高
-> MoveControl 朝节点前进
-> JumpControl 被激活
-> 实体获得跳跃意图或竖直速度
-> 重力和碰撞完成腾空与落地
-> Navigation 确认到达高处节点
~~~

### 6.4 平地跳跃与特殊生物

平地路径节点高度近似相同，前方也没有需要越过的碰撞形状，因此通用移动控制器一般不会触发跳跃。

兔子、史莱姆或拥有扑击 Goal 的生物可能因专属行为在平地跳跃。这不是通用地面 A* 的规则。

### 6.5 跳跃限制

能否产生向上边取决于生物步高、最大抬升、体型、上方净空、目标表面、过渡碰撞和方块类型。

过高墙体、低矮顶棚、栅栏和封闭墙角都会使向上后继无效。

## 7. 下落如何处理

### 7.1 向下寻找落点

当水平邻居为 OPEN，即脚下暂时没有支撑时，节点生成器会沿该列向下寻找可站立表面：

1. 尝试水平移出边缘；
2. 发现候选位置是开放空间；
3. 沿 Y 轴向下检查；
4. 找到合法支撑和足够净空；
5. 计算当前节点到落点的高度差；
6. 高度允许时建立向下连接；
7. 过深、危险或不可站立时拒绝。

### 7.2 空中体素不是普通落脚节点

下落不需要为每个空气格生成节点链，路径表达的是：

~~~text
悬崖边节点 -> 较低落脚节点
~~~

这样能减少节点数量，并避免 A* 把空中位置当作可以停留的状态。

### 7.3 实际下落由重力执行

路径只表明高处能够连接到低处。实体离开边缘后，由速度、碰撞和重力完成下落。接近低处节点后，Navigation 才推进路径。

过大的落差通常不会成为普通地面路径的一部分。允许高度与生物的安全下落能力和节点规则有关。

## 8. 路径如何被跟随

Path 保存节点序列和当前索引。每个 tick，Navigation 大致执行：

1. 获取实体用于寻路的位置；
2. 判断下一节点是否到达；
3. 到达后推进索引；
4. 检查能否安全跳过中间节点；
5. 检查路径是否长期无进展；
6. 把当前目标节点交给移动控制器；
7. 路径完成、无效或超时时停止。

### 8.1 节点到达容差

实体不需要精确位于节点中心。Navigation 使用与实体尺寸有关的接近阈值，足够靠近下一节点时就推进路径。

### 8.2 路径简化

当前位置能够直接安全到达后续节点时，Navigation 可以跳过中间节点，使空旷区域的运动更直。直接路径检查仍需验证碰撞和地面通行条件。

### 8.3 超时与卡住

实体长时间无法接近下一节点时，Navigation 可能停止或等待重算。常见原因包括：

- 世界在寻路后变化；
- 门或动态碰撞体阻挡；
- 其他生物堵塞；
- 实体被推离路径；
- 规划节点可达，但运动执行不稳定；
- 只获得了接近目标的部分路径。

## 9. 怪物如何追击玩家

### 9.1 先选择攻击目标

目标选择 Goal 会根据生物类型和状态寻找玩家，通常考虑：

- 玩家是否存活；
- 玩家是否处于允许被选中的状态；
- 距离是否在跟随范围内；
- 是否满足可见性或记忆条件；
- 是否存在更高优先级行为。

找到玩家不等于已经存在可达路径。

### 9.2 近战追击流程

通用近战怪物常使用 MeleeAttackGoal 或其子类：

1. 获取当前攻击目标；
2. 请求 Navigation 计算到目标附近的路径；
3. 沿路径接近目标；
4. 周期性检查目标新位置；
5. 必要时重新计算路径；
6. 进入攻击距离且冷却结束后攻击。

### 9.3 不会每 tick 完整重算

MeleeAttackGoal 保存目标上次用于寻路的位置，并维护 updateCountdownTicks。是否重算会受以下因素影响：

- 倒计时是否结束；
- 玩家是否移动足够距离；
- 怪物与玩家的距离；
- 当前路径是否完成或失败；
- 是否能够观察目标；
- 上一次寻路是否失败。

寻路失败时通常会延长等待，避免怪物在不可达玩家附近每 tick 重复执行昂贵搜索。

### 9.4 路径终点在玩家附近

玩家有自己的碰撞体，怪物不需要占据玩家身体内部的节点。寻路只需让怪物接近目标，攻击逻辑再依据距离、包围盒和攻击范围决定能否攻击。

### 9.5 玩家移动后的表现

玩家移动后，怪物通常继续沿旧路径走一段时间，再按重算条件更新路径。这是在响应速度和计算量之间的折中。

### 9.6 玩家不可达时

玩家位于封闭墙后、高台、深坑另一侧或搜索范围外时，可能出现：

- 沿部分路径走到最接近位置；
- 在墙边或悬崖边等待；
- 当前路径超时后停止；
- 玩家移动或环境变化后再次尝试；
- Goal 因距离、可见性或目标有效性变化而结束。

“已经锁定玩家”不等于“必定存在完整可达路径”。

## 10. 常见误解

### 10.1 是完整三维 A* 吗？

节点坐标是三维的，但普通地面生物的节点主要位于表面。它不是任意空气体素都能通行的体积图。

### 10.2 A* 会计算跳跃轨迹吗？

通常不会。A* 连接低处和高处落脚节点，跳跃弧线由移动控制和实体运动完成。

### 10.3 脚下是实心方块就一定能站吗？

不一定。还要检查完整包围盒、实际碰撞形状、节点类型、危险代价和到达过程。

### 10.4 找到玩家就会每帧重算路径吗？

不会。追击 Goal 根据倒计时、目标移动、距离、可见性和失败状态决定何时重算。

### 10.5 有路径就一定不会卡住吗？

不会。路径只描述导航可达性，实际执行还受碰撞、其他实体、速度、门状态和世界变化影响。

### 10.6 所有怪物使用同一套规则吗？

不会。不同生物可以拥有不同节点代价、体型、跟随范围、移动控制器、Goal，以及开门、游泳、飞行、攀爬或特殊跳跃能力。
