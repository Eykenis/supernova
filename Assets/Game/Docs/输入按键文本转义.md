# 输入按键文本转义

游戏内任意文本都可以写一个转义标记，运行时自动替换成当前实际键位。
玩家在设置里改键后，已显示的文本会立刻跟着变，不需要重启或手动刷新。

例如文本里写：

```
按{{input:Gameplay/Move|compact}}移动
```

游戏里显示：

```
按WASD移动
```

## 语法

```
{{input:<映射>/<动作>}}
{{input:<映射>/<动作>|compact}}
{{input:<映射>/<动作>.<分量>}}
```

| 写法 | 显示 | 用途 |
| --- | --- | --- |
| `{{input:Gameplay/Jump}}` | `Space` | 普通按键 |
| `{{input:Gameplay/Move}}` | `WASD` | 方向键自动拼成一串 |
| `{{input:Gameplay/Move.up}}` | `W` | 只取某一个分量 |
| `{{input:UI/Pause}}` | `Esc` | UI 按键 |

分量名是 `up` / `down` / `left` / `right`（大小写不敏感）。

有备用键的动作只显示主键：`Gameplay/Crouch` 同时绑了左右 Ctrl，但显示成
`Ctrl` 而不是 `Ctrl | Right Ctrl` —— 提示语只需要告诉玩家按哪一个。

`Gameplay/Move` 是纯 composite（没有单键），所以裸写和加 `|compact` 一样都输出
`WASD`。

## 转义

标记前加一个反斜杠，就原样显示不替换：

```
\{{input:Gameplay/Jump}}   →   {{input:Gameplay/Jump}}
```

写错的动作路径不会报错也不会变成空白，而是原样保留，方便一眼看出拼错了：

```
{{input:Gameplay/NotExist}}   →   {{input:Gameplay/NotExist}}
```

## 可用的动作路径

路径就是 `映射名/动作名`，全部定义在
`Assets/Game/Runtime/Input/GameInputDefinitions.cs`：

- `Gameplay/` — `Move` `Look` `Jump` `Crouch` `Sprint` `PrimaryAction`
  `SecondaryAction` `Interact` `ThrowPickaxe` `ToggleEquipment`
  `Hotbar1`…`Hotbar5` `HotbarScroll` `TogglePerspective` `MagnetRotate`
- `UI/` — `Pause` `ToggleLoadout` `Navigate` `Submit` `Cancel`
  `Point` `Click` `RightClick` `MiddleClick` `ScrollWheel`
- `Debug/` — `Mission` `Hud` `FlyToggle` `Smile` `Hit` `Die`
  `Recover` `FlyUp` `FlyDown` `FlyFast`
- `Spectator/` — `LookHold` `OrbitHold` `Up` `Down` `Fast`
- `StructureEditor/` — `Save` `Paint` `Erase`
- `Examples/` — `PortalReset` `PrototypeReset`

改键位要改 `GameInputDefinitions.cs`，然后跑一次菜单
`Tools/Supernova/Input/Rebuild Game Input Actions` 重新生成
`Assets/Game/Config/Input/GameInputActions.inputactions`。

## 在哪里能用

`TextMeshPro` 文本和旧版 `UnityEngine.UI.Text` 都支持，直接把标记写进文本内容即可，
不需要挂任何组件、不需要写代码。

场景里手放的文本（例如 `Assets/Scene/SpawnShelterStoneTest.scene` 里那几个
世界空间提示牌）直接写标记即可，进游戏自动变成实际键位。

### 代码里动态赋值必须走 SetText

**运行时**改文本内容时，不要直接写 `label.text = ...`，要用：

```csharp
InputPromptTextRuntime.SetText(promptLabel, "PRESS {{input:Gameplay/Interact}} TO BUY");
```

原因：常驻组件只在场景加载时扫描一次文本，运行中新建或改写的文本赶不上那次
扫描，会**原样显示 `{{input:...}}`**。`SetText` 在赋值的同时挂好预处理器，
不依赖事件时机。TMP 和旧版 `Text` 都有对应重载。

已经这样接好的地方：`MissionUiView`（objective / prompt / result）、
`ShopProductDisplay`。新增运行时文本请照此办理。

要在代码里手动解析（比如拼给非 UI 的地方用），调用：

```csharp
string text = InputPromptResolver.Resolve("按{{input:Gameplay/Move}}移动");
```

## 实现

- `Assets/Game/Runtime/Input/InputPromptResolver.cs`
  正则匹配并替换标记，是纯逻辑，可单独测试。
- `Assets/Game/Runtime/Input/InputPromptTextRuntime.cs`
  游戏启动时自动创建常驻对象（`RuntimeInitializeOnLoadMethod`），扫描场景里
  所有文本。TMP 走 `ITextPreprocessor`，不改写 `text` 原文，因此模板不会被
  替换结果覆盖，改键后能反复重算；旧版 `Text` 没有预处理接口，所以额外缓存
  了一份原始模板。订阅 `GameInput.BindingsChanged`，改键后刷新已注册文本。

注意：TMP 每个文本只能挂一个 `textPreprocessor`。如果某个文本已经有别的
预处理器，运行时会打一条 warning 并保留原有的，该文本的标记不会被替换。
