# 体素与距离场生成

本文总结当前工程中与体素数据、类型、距离场采样和网格生成直接相关的实现。

## 1. 体素数据模型

### 1.1 单个体素块

单个 chunk 固定保存 `32 × 32 × 32` 个采样点。每个采样点现在由两部分组成：

- `float density`：连续密度/距离场值；
- `VoxelTypeId type`：离散体素类型，底层为 `ushort`。

类型约定：

- `VoxelTypeId.Air`（值 `0`）保留给空气；
- `VoxelTypeId.Default`（值 `1`）是兼容旧代码的默认实体类型；
- 游戏可以从 `2` 开始定义石头、矿物、土壤等任意类型。

数据使用连续数组保存，索引公式仍为：

```text
index = x + 32 * (y + 32 * z)
```

`VoxelVolume.SetSample(x, y, z, density, type)` 可以同时写入密度和类型。旧的密度索引器仍然可用：把采样点设为空时类型自动归一化为 `Air`，把空气重新设为实体时自动使用 `Default`。

### 1.2 密度约定

默认等值面为 `isoLevel = 0`：

- `density >= isoLevel` 且 type 非 Air：实体；
- 其他情况：对当前类型的场而言是外部。

## 2. 多类型 Marching Cubes

### 2.1 按类型拆分二值场

网格构建先缓存 chunk 的 `33³` 个 `VoxelSample`，收集其中出现的实体类型，然后对每个类型分别执行一次 Marching Cubes：

```text
inside(type T) = density >= isoLevel && voxel.type == T
```

因此：

- 相同类型的相邻采样点属于同一个二值场，会自然聚类成连续表面；
- 不同类型永远不会在同一次 polygonise 中被当成同一实体；
- 每个类型的三角形写入独立 submesh，材质可以按 type 分配。

### 2.2 不同类型边界的分离

如果一条 cube edge 的两端都是实体但 type 不同，两种类型都会生成自己的边界面。为避免两个面完全重合并产生 z-fighting，各自的交点会从边中点向自己的采样端缩进 `0.05 voxel`：

```text
Type A surface: t = 0.45
Type B surface: t = 0.55
```

这样类型边界会留下 `0.1 voxel` 的可见微缝，明确表达“分离”。实体与空气之间仍使用标准边中点 `t = 0.5`。

这是当前采用的明确、稳定方案；代价是类型数量增加时，Marching Cubes 的 cell 遍历次数近似按活跃类型数线性增长。

### 2.3 Submesh 与材质

`VoxelMeshData` 保存：

- 合并后的 `Vertices` / `Triangles`（兼容原统计代码）；
- 按 `VoxelTypeId` 分组的三角形；
- `SubmeshTypes`，其顺序与 Unity Mesh 的 submesh 顺序一致。

`VoxelTypeMaterialBinding` 用 `ushort type -> Material` 配置材质。`MinecraftCaveInfiniteWorld` 会按 `SubmeshTypes` 为 `MeshRenderer.sharedMaterials` 生成材质数组；未配置的类型使用原 chunk fallback material。

## 3. 体素修改

`InfiniteVoxelWorld` 新增：

- `TryGetSample` / `GetSampleOrDefault`；
- `SetVoxel(worldX, worldY, worldZ, density, type)`。

`MinecraftCaveInfiniteWorld.TrySetVoxelAndRebuild` 提供带 `VoxelTypeId` 的重载。即使密度符号不变，只要 type 改变，也会重建当前及相关边界 chunk。

## 4. 性能观测点

原有 Profiler Marker 保持不变。多类型场景应额外关注：

- 单 chunk 活跃类型数量；
- `Voxel.Mesh.MarchingCubes` 随类型数量的增长；
- submesh 数和材质 draw call 数。

当前静态采样缓存仍不支持并发调用同一个 mesher。
