# 洞穴草地渲染

风格化洞穴草地的实现说明。美术方向参考《塞尔达传说：旷野之息》：无贴图、
法线继承地表、根→尖渐变、根部 AO、边缘透光。

---

## 一、Forward 逐对象光照索引（最重要，先读这一节）

**结论：`Graphics.DrawMeshInstanced` 绘制的物体在 Forward 模式下收不到任何点光 / 聚光灯。**

三个 Renderer 资产均为 `m_RenderingMode: 0`（Forward，非 Forward+）。
Forward 下附加光通过 `unity_LightIndices` / `unity_LightData` 传给着色器，而这两个
数组由 Unity 在剔除阶段**按 renderer 逐个填充**
（`UniversalRenderPipeline.cs` 的 `GetPerObjectLightFlags`，仅在非 Forward+ 时附加
`PerObjectData.LightData` 与 `PerObjectData.LightIndices`）。

`Graphics.DrawMeshInstanced` 只提交矩阵，不产生 renderer 条目，于是：

```
unity_LightData.y == 0
  → GetAdditionalLightsCount() 返回 0
  → 标准 URP 光照循环一次都不执行
```

这项修复最初在 `InfiniteCaves.scene` 的无场景灯光基线上完成：洞穴主要照明来自
工具和运行时生成的点光/聚光灯。当前正式场景已经切换为
`DenseJigsawRegion.scene`，但 `Graphics.DrawMeshInstanced` 缺少逐 Renderer 光照索引的
限制没有改变；如果仍走标准 Forward 附加光循环，草会忽略这些局部灯光。

### 采用的解法

草的 Fragment Shader **自行遍历全局灯光数组**，绕过 `unity_LightIndices`：

```hlsl
int visibleLightCount = min((int)_AdditionalLightsCount.x, MAX_VISIBLE_LIGHTS);
for (int lightIndex = 0; lightIndex < visibleLightCount; lightIndex++)
{
    Light light = GetAdditionalPerObjectLight(lightIndex, input.positionWS);
    ...
}
```

可行的依据（URP 14.2.0-t1）：

- `RealtimeLights.hlsl` 的 `GetAdditionalPerObjectLight(int perObjectLightIndex, float3 positionWS)`
  接受**原始全局索引**，不经过 `GetPerObjectLightIndex` 转换 → 复用 URP 自身的
  灯光解包与距离/聚光衰减，无需重写。
- `Input.hlsl` 中 `_AdditionalLightsPosition/Color/Attenuation/SpotDir[MAX_VISIBLE_LIGHTS]`
  是无条件声明的全局数组，与 per-object 索引无关。

代价与边界：

- 上限为 URP 的全局可见灯数 `MAX_VISIBLE_LIGHTS`（桌面端默认 256，移动端更低），
  而非每物体 2/4/8。洞穴同时可见灯很少，实际不构成瓶颈。
- 不做逐物体裁剪，因此是"每片草 × 每盏可见灯"。若将来洞内同时存在大量灯，
  应改走 Forward+（`m_RenderingMode: 2`，clustered 光照，天然支持实例化绘制），
  但那会改变整个项目的渲染路径，需重新验证石壁亮度与性能。

**衰减一致性**：`SoftenedPunctualAttenuation()` 已抽出到
`Assets/Game/Materials/Lighting/SoftFalloffAttenuation.hlsl`，草与石壁共用，
所以草不会和洞壁呈现两条不同的衰减曲线。参见 [SoftFalloffLighting.md](SoftFalloffLighting.md)。

### 实际 URP 版本

`Packages/manifest.json` 写的是 `17.1.0`，**不可信**。真实解析结果是
`Library/PackageCache/com.unity.render-pipelines.universal@14.2.0-t1`（团结引擎分支）。
查 URP 源码时请以 PackageCache 下的实际目录为准。

## 二、资产链路

全部路径集中在 `Assets/Game/Editor/ProjectAssetPaths.cs`（项目规范禁止硬编码路径）。

```
CaveBiomeCatalog（噪声选择 biome）
  └─ CaveBiomeDefinition        Config/Biomes/Grassy.asset
       ├─ 植被色调：根色 / 尖色 / rim 色 / 色调抖动 / 风响应倍率
       └─ surfaceBrushes
            └─ CaveSurfaceBrushDefinition   Config/SurfaceBrushes/Grass.asset
                 ├─ 形状：LOD 三档 / 淡出带 / 直立偏置 / 簇格 / 风参数
                 ├─ material  Materials/Vegetation/CaveGrassBlade.mat
                 └─ lodTiers  Models/Vegetation/CaveGrassBladeLod{0,1,2}.asset
                                   ↑ 由 CaveGrassBladeMeshBuilder 生成
```

**颜色属于 biome，形状属于 brush。** 这是 Minecraft grass colormap 的思路：
一份共享材质服务所有 biome，新增生物群系只需填颜色，不需要新材质或新 shader 变体。
颜色通过每 (brush, biome) 一个缓存的 `MaterialPropertyBlock` 下发——这正是
`Graphics.DrawMeshInstanced` 那个此前一直传 `null` 的参数的正当用途。

所有资产由 `Tools/Minecraft Caves/Rebuild Surface Biome Assets`
（`CaveSurfaceBiomeAssetBuilder`）确定性重建。该菜单用 `CopySerialized` 覆盖既有
网格资产而非删除重建，以**保留 GUID**，这是 `Grass.asset` 的网格引用能在重建后
存活的原因。

> `EnsureShaderMaterial` 在找不到草 shader 时会 `throw`，**不会**静默回落到
> URP Lit。静默回落仍会渲染出绿色的草，从而把 shader 编译错误藏在"看起来差不多"
> 的结果后面。

## 三、生成与确定性

放置在 `CaveSurfaceBrushGenerator.Generate` 内完成，运行于网格构建之后。

### 法线继承地表

`SampleTriangle` 现在同时输出重心权重，用它对 `meshData.Normals` 插值，得到平滑的
marching-cubes 地表法线。

时序是安全的：`MinecraftCaveInfiniteWorld` 先调用 `CreateMesh()`（其内部执行
`VoxelMeshData.PrepareForUpload()` 完成法线归一化），之后才调用
`SpawnSurfaceContent`。若将来调换这两步顺序，草的法线会全部变成零向量并回落到面法线。

**为什么重要**：逐叶几何法线在弯曲的 marching-cubes 表面上会逐帧闪烁。
把姿态法线烘进实例矩阵、由 shader 取实例的 local up 作为着色法线之后，
整片草作为一个连续曲面着色——这是 BotW 那种平静观感的核心，
在本项目比在任何平地游戏里都更关键，因为洞穴表面本身是曲面。

### 直立偏置

`uprightBias`（默认 0.65）把姿态从地表法线向垂直方向混合。
`minimumVerticalAlignment = 0.6` 允许最大约 53° 的坡，完全对齐法线会让草在坡上躺倒。
天花板笔刷（`OutwardNormal.y < 0`）向下偏置，藤蔓仍然垂挂。

`CaveSurfacePlacement` 因此有两个法线，**不要混用**：

| 字段 | 用途 |
|---|---|
| `OutwardNormal` | 朝向门控与表面偏移。**语义不可更改**，既有测试断言它 `>= 0.6` / `<= -0.6` |
| `StanceNormal` | 实际立起的轴，烘进实例矩阵，被 shader 当作着色法线 |

### 成簇（`CaveSurfaceClumpField`）

纯随机散布看着像人工地毯。簇场把位置量化到簇格，同格共享高度 / 宽度 / yaw 偏置，
于是出现成片的高矮与朝向斑块（Ghost of Tsushima 的 Voronoi clump 手法，
是"看起来像长出来的"性价比最高的一步）。

**颜色不走 CPU 簇场。** 叶片 Shader 用同一套簇格量化在 GPU 上自行哈希出色调
（`GrassClumpHash`），因此逐簇色斑不需要任何逐实例数据传输。代价是
`_ClumpCellSize` 必须与笔刷的簇格尺寸保持一致，否则颜色斑块会与高矮/朝向斑块
互相错开。该值由渲染器随 MPB 一起下发，已自动同步。

两条不变量，均有测试覆盖：

1. **按世界体素坐标采样，绝不用 section 局部坐标。** 跨 chunk 的簇必须从两侧解析到
   同一格，否则 section 接缝处会出现可见的分界。
   （`CaveSurfaceClumpFieldTests.SectionSeams_ResolveToTheSameClump`）
2. **簇场自带哈希流，不从放置用的 `DeterministicRandom` 取值。** 在既有取值之前
   插入任何一次 `NextDouble()` 都会平移之后的全部随机序列，静默重排所有地表内容。

垂直簇格与水平簇格分离，因为洞穴地面是层叠的，共用一根簇柱会把互不相干的岩台绑在一起。

### 黄金值

`CaveSurfaceBrushTests` 里的 `GoldenFirstPlacementX` 钉住首个放置的精确 x。
"两次运行一致"的断言查不出**整体平移**的分布；黄金值可以。
若确实有意改动放置随机流，再更新该常量。

## 四、渲染路径（`CaveSurfaceInstanceRenderer`）

每帧 `LateUpdate`，逐 (brush, biome) 分组、逐批处理：

```
空间排序（Morton）→ 切批(≤1023) → 逐批 bounds
   → 距离剔除 → 视锥剔除 → 选 LOD 档 → DrawMeshInstanced
```

- **先空间排序再切批**。否则一批会横跨整个 section，其 bounds 覆盖一切，
  逐批剔除与逐批 LOD 就退化成和整组一刀切没有区别。
- **逐批 bounds**，取代此前"整组一个 bounds"导致的整个 32×32 section 全有/全无弹出。
- **视锥平面每相机每帧只算一次**并静态缓存，而非每个 section 各算一遍。
- **LOD 按批中心距离选档**（12m / 25m / 之外），因为批在空间上紧凑，
  切换发生在批边界而不是穿过一片草的中间。
- **距离淡出**：叶片在 33→45m 逐渐缩到零高度，而不是突然消失。

### LOD 与覆盖率补偿

| 档位 | 叶片数 | 每叶段数 | 三角数 | 根部半宽 |
|---|---|---|---|---|
| LOD0 | 5 | 5 | 50 | 0.018 |
| LOD1 | 4 | 3 | 24 | 0.024 |
| LOD2 | 3 | 1 | 6  | 0.034 |

远档叶片数减少的同时**加宽叶片**（Ghost of Tsushima 的做法），使远近剪影面积连续，
否则草地会随距离明显变稀。

LOD0→LOD1 的切换本质上仍是一次网格替换，靠"边界放在叶片已经很小处 + 加宽补偿"
**缓解而非消除**。若实机观感仍有跳变，下一步才考虑 dither 交叉淡入（会使该带内
draw call 翻倍），不要预先实现。

### 已知局限：`Camera.main` 与传送门相机

实例化绘制提交一次、对所有相机重放，因此剔除与 LOD 只跟随主相机。
当前 `DenseJigsawRegion` 已接入 `DenseJigsawPortalBridge`，而
`PortalExampleGate` 会创建传送门相机；传送门画面可能看到按玩家主相机选择的草
LOD/剔除结果。这是现存限制，不再是假设性的后续场景。需要修正时，改为在
`RenderPipelineManager.beginCameraRendering` 中按实际渲染相机提交，并避免递归
传送门渲染重复绘制。

### 性能观测

`ProfilerMarker`：`CaveSurface.Instances.Cull` / `CaveSurface.Instances.Draw`。
若逐批剔除的 CPU 开销在数百 section 下成为热点，升级路径是改为单一集中管理器
遍历全部 section，取代每个 section 各自一个 `LateUpdate`。

## 五、叶片网格通道契约

由 `CaveGrassBladeMeshBuilder` 生成，`CaveGrassBladeMeshTests` 守护：

| 通道 | 内容 |
|---|---|
| `POSITION` | 叶片几何。**根部顶点 `y` 严格为 0** |
| `NORMAL` | 叶面法线（shader 按 `_NormalBlend` 与姿态法线混合） |
| `UV0` | x = 叶宽比，y = 根→尖比（驱动风力权重、颜色渐变、根部 AO） |
| `UV1` | x = 叶索引（相位/色相打散），y = 该叶高度倍率 |
| `COLOR`, `UV2`, `UV3` | **保持空白**，预留给交互（踩踏 / 割草 / 燃烧） |

- **根部 `y == 0` 是硬契约**：风力位移按 `UV0.y` 加权，根部权重为零才不会让草脱离地面。
  有专门的测试守这一条。
- 叶片**单面** + shader `Cull Off` + `VFACE` 翻转背面法线，取代此前用重复顶点做双面的
  占位实现，几何量减半。
- 网格 bounds 额外留出风力位移余量：实例化绘制按网格 bounds 做视锥剔除，
  被风吹出 bounds 的叶尖会在仍然可见时被剔掉。

`CaveSurfacePlaceholderVisual`（旧的 3 片平面四边形）**仍在服务藤蔓的 prefab 路径**，
未删除。它的 `Grass` 分支现在只被 prefab 版占位资产使用。

## 六、Shader 参数

`Assets/Game/Shaders/Vegetation/CaveGrassBlade.shader`
（`Supernova/Vegetation/Cave Grass Blade`），手写 pass，不继承 URP Lit
（需要自定义灯光循环）。`#pragma target 3.0`，无几何着色器、无曲面细分、无 compute。

Pass：`UniversalForward` / `ShadowCaster` / `DepthOnly` / `DepthNormals`。
**四个 pass 共用同一套顶点动画**，否则深度、阴影与颜色会各自认为叶片在不同位置
（自阴影错位、深度测试错误）。缺 `DepthNormals` 会让草在 SSAO 缓冲里打洞。

| 参数 | 作用 |
|---|---|
| `_RootColor` / `_TipColor` | 根→尖渐变（由 biome 覆盖） |
| `_RimColor` / `_RimPower` / `_RimStrength` | 边缘背光，伪次表面散射 |
| `_RootOcclusion` | 根部压暗，伪冠层自阴影。成片草地不显得像一张平色卡的关键 |
| `_TintVariation` / `_HueJitter` | 逐簇 / 逐实例色调打散 |
| `_WindStrength/Frequency/ScrollSpeed/BendExponent/_WindDirection` | 风；`BendExponent` 越高，基部越硬、只有叶尖摆动 |
| `_HeightJitter` | 逐实例高度变化 |
| `_NormalBlend` | 地表法线继承强度（0 用叶面法线，1 完全用地表法线） |
| `_ClumpCellSize` | 簇格尺寸 xy，**必须与笔刷簇格一致**，否则色斑与高矮斑块错开 |
| `_FadeStartDistance` / `_FadeEndDistance` | 高度淡出带 |
| `_SupernovaGrassInteractionParams` | **预留**，已声明未使用 |

属性刻意**声明为普通 uniform 而非放进 `UnityPerMaterial`**：草走
`DrawMeshInstanced`（不经 SRP Batcher），且渲染器需要用
`MaterialPropertyBlock` 逐组覆盖颜色与风；位于 `UnityPerMaterial` 中的属性
无法可靠地被 MPB 覆盖。

### 逐实例变化用整数哈希，不用属性数组

`GrassInstanceHash` 从量化后的实例原点做整数位混合。相比
`MaterialPropertyBlock.SetVectorArray`：零 CPU 成本、零内存、天然跨 section 连续、
不随排序失效。

**必须是整数位运算哈希，不能用 `frac(sin(dot(...)))`**——后者在世界坐标达到数千米时
会出现可见条带，而本作的洞穴世界正好会走到那么远。
`CaveSurfaceClumpFieldTests.Attributes_RemainVariedFarFromTheOrigin` 守这一条。

## 七、后续工作

- **交互（踩踏 / 割草 / 燃烧）**：本轮仅预留通道。BotW 的经验是，让草成为
  *系统*（可燃、可割、可藏身）带来的玩家参与远高于再多堆两万片叶子。
  实现方式：跟随玩家的位移 RenderTexture，玩家/矿车/生物写入弯折向量，
  顶点着色器采样；`COLOR` / `UV2` / `_SupernovaGrassInteractionParams` 已为此留空。
  规模再上一个量级时应转向 `DrawMeshInstancedIndirect` + compute 剔除
  （Ghost of Tsushima 路径）。
- **更多生物群系**：只需新建 `CaveBiomeDefinition` 并填植被色调，无需新材质。
- **URP 质量档分级**：目前三档共用一套草参数，可按档位调 LOD 距离与密度。
