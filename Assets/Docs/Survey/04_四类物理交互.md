# 四类物理交互

项目中的物理交互可以归纳为四类。它们分别解决不同问题：

| 类别 | 核心问题 | 主要作用对象 | 模型 |
|---|---|---|---|
| 磁力牵引 | 如何把物体拉到玩家面前 | Rigidbody 物体 | PD 弹簧 |
| 绳索 | 如何限制玩家与锚点的距离 | CharacterController 玩家 | 单边距离约束 |
| 冲量计算 | 碰撞、枪击和爆炸如何传递动量与伤害 | 怪物、宝物、动态物体 | 动量/冲量模型 |
| 地形支撑 | 体素被破坏后哪些部分应当坍塌 | 静态体素与动态体素块 | 六连通支撑图 |

## 1. 磁力牵引

实现主体是 [FirstPersonMagnetInteractor.cs](../../Game/Runtime/Gameplay/FirstPersonMagnetInteractor.cs)。

磁力主要作用于带有 Rigidbody 的物体，例如：

- 宝物。
- 矿物掉落。
- 怪物。
- 动态体素碎块。
- 其他允许被磁力选中的刚体。

投掷出去的飞镐是特殊情况：它不会被普通磁力拉回玩家，而是转入“绳索拉动玩家”的模式。

### 1.1 目标选择

磁力首先通过摄像机方向射线寻找目标：

    摄像机 → Raycast → 可吸附 Collider → attachedRigidbody

如果准星没有直接命中，还会在视线附近做球形范围检测，实现一定的瞄准辅助。

目标必须满足：

- 带有非 Kinematic 的 Rigidbody。
- 不属于玩家自身。
- 在有效吸取距离内。
- 普通物体需要与玩家之间不存在地形遮挡。

### 1.2 位置牵引：PD 弹簧

磁力并不直接把物体传送到目标点，而是使用弹簧力。

设目标持有点为 \(\mathbf x_t\)，物体质心为 \(\mathbf x_b\)，位置误差：

\[
\mathbf e=\mathbf x_t-\mathbf x_b
\]

玩家或持有点速度为 \(\mathbf v_t\)，物体速度为 \(\mathbf v_b\)，相对速度：

\[
\mathbf v_r=\mathbf v_t-\mathbf v_b
\]

磁力：

\[
\mathbf F=k_p\mathbf e+c\mathbf v_r
\]

其中：

- \(k_p\)：位置弹簧强度，默认 300。
- \(c\)：速度阻尼，默认 90。

第一项负责把物体拉向目标；第二项负责抑制振荡。如果只有弹簧项，物体会不断越过目标点来回摆动。

### 1.3 力和加速度限制

计算出的磁力要经过两次限制：

\[
\|\mathbf F\|\le F_{\max}
\]

\[
\|\mathbf F\|\le ma_{\max}
\]

因此最终限制为：

\[
\|\mathbf F\|
\le
\min(F_{\max},ma_{\max})
\]

默认：

- 最大磁力 \(F_{\max}=800N\)。
- 最大加速度 \(a_{\max}=40m/s^2\)。

第二个限制意味着：质量很小的物体也不会因为相同的 800N 力而获得极端加速度。

由于：

\[
\mathbf a=\frac{\mathbf F}{m}
\]

重物体在未触发加速度限制时会比轻物体更难拉动。

### 1.4 向上牵引限制

为了避免玩家无限向上抬升重物，最大升力随高度降低。

设物体相对抓取时的升高量为：

\[
\Delta h=\max(0,h-h_0)
\]

最大升力：

\[
F_{\mathrm{lift,max}}
=
\frac{F_{\mathrm{lift},0}}
{1+\alpha\Delta h}
\]

其中：

- \(F_{\mathrm{lift},0}\)：基础最大升力。
- \(\alpha\)：每米衰减系数。

高度越高，向上的可用磁力越小；水平方向的牵引不受这个公式直接影响。

### 1.5 朝向控制

玩家旋转被吸附物体时，使用旋转 PD 控制：

\[
\boldsymbol\tau
=
k_R\theta\hat{\mathbf a}
-c_R\boldsymbol\omega
\]

其中：

- \(\theta\)：当前朝向与目标朝向之间的角度。
- \(\hat{\mathbf a}\)：旋转轴。
- \(\boldsymbol\omega\)：当前角速度。
- \(k_R\)：朝向弹簧。
- \(c_R\)：角速度阻尼。

扭矩会按最大扭矩限幅，然后使用 ForceMode.Acceleration 施加，因此朝向控制基本不依赖物体质量。

### 1.6 磁力牵引流程

~~~mermaid
flowchart LR
    A["射线/范围查询"] --> B["取得 Rigidbody"]
    B --> C["计算目标位置误差"]
    C --> D["PD 弹簧力"]
    D --> E["力、加速度、升力限幅"]
    E --> F["AddForceAtPosition"]
    F --> G["PhysX 更新位置与碰撞"]
~~~

## 2. 绳索

绳索数学位于 [RopeConstraint.cs](../../Game/Runtime/Gameplay/RopeConstraint.cs)。

绳索连接的是：

- 锚点：投掷后停留在世界中的飞镐。
- 受约束对象：玩家 CharacterController。

它不是弹簧，而是一个不可伸长的单边距离约束：

\[
\|\mathbf x-\mathbf a\|\le L
\]

其中：

- \(\mathbf x\)：玩家绳索连接点。
- \(\mathbf a\)：飞镐锚点。
- \(L\)：当前绳长。

“单边”表示：

- 玩家在绳长范围内时，绳子松弛，不施加约束。
- 玩家试图超过绳长时，绳子才绷紧。
- 绳子可以拉，不能推。

### 2.1 径向与切向速度

定义锚点到玩家的向量：

\[
\mathbf r=\mathbf x-\mathbf a
\]

绳索方向：

\[
\mathbf n=\frac{\mathbf r}{\|\mathbf r\|}
\]

玩家速度可以分成径向和切向两部分：

\[
\mathbf v_r
=
(\mathbf v\cdot\mathbf n)\mathbf n
\]

\[
\mathbf v_t
=
\mathbf v-\mathbf v_r
\]

其中：

- \(\mathbf v_r\)：改变绳索长度的速度。
- \(\mathbf v_t\)：沿绳索球面运动的速度。

### 2.2 绳索绷紧约束

当玩家位于满绳长度，且仍在向外运动：

\[
\mathbf v\cdot\mathbf n>0
\]

项目会移除向外径向速度：

\[
\mathbf v'
=
\mathbf v-
(\mathbf v\cdot\mathbf n)\mathbf n
\]

因此：

\[
\mathbf v'\cdot\mathbf n=0
\]

但切向速度保持不变，所以玩家能够继续围绕锚点摆荡。

如果把整个速度清零，玩家会挂在绳子末端不动；如果持续向锚点施力，则表现会更像牵引光束，而不是绳索。

### 2.3 位置纠正

仅修正速度还不够。由于重力已经在本帧产生了一小段向外位移，绳索可能逐帧拉长。

当：

\[
\|\mathbf r\|>L
\]

位置修正为：

\[
\Delta\mathbf x
=
\mathbf r
\left(
\frac{L}{\|\mathbf r\|}-1
\right)
\]

等价于：

\[
\Delta\mathbf x
=
-(\|\mathbf r\|-L)\mathbf n
\]

修正后玩家重新位于半径为 \(L\) 的球面上。

### 2.4 摆荡输入

移动输入不能直接沿绳索方向推动玩家，而要投影到绳索切平面。

输入方向为 \(\mathbf d\)，其切向部分：

\[
\mathbf d_t
=
\mathbf d-
(\mathbf d\cdot\mathbf n)\mathbf n
\]

摆荡加速度：

\[
\mathbf a_{\mathrm{swing}}
=
a_s
\frac{\mathbf d_t}{\|\mathbf d_t\|}
\]

这意味着：

- 朝锚点按键：基本不产生摆荡推力。
- 背离锚点按键：基本不产生摆荡推力。
- 沿圆弧方向输入：增加摆荡速度。

### 2.5 瞬时拉扯

绳子第一次从松弛变为绷紧时，会产生一次向内速度变化。

向外速度：

\[
v_{\mathrm{out}}=\mathbf v\cdot\mathbf n
\]

拉扯速度：

\[
\Delta\mathbf v_{\mathrm{yank}}
=
-\mathbf n
\min(v_{\mathrm{out}}k_y,v_{\max})
\]

玩家下落越快，绳子绷紧时的猛拽越明显。

### 2.6 收放绳

绳长更新：

\[
L'
=
\operatorname{clamp}
(L-us_r\Delta t,L_{\min},L_{\max})
\]

其中：

- \(u>0\)：收绳。
- \(u<0\)：放绳。
- \(s_r\)：收放速度。

收绳时，系统还会确保玩家获得与实际收绳速率匹配的向内速度，而不是只缩短数值却不移动玩家。

### 2.7 绳索流程

~~~mermaid
flowchart LR
    A["连接飞镐锚点"] --> B["记录初始绳长"]
    B --> C["处理收放绳"]
    C --> D["首次绷紧时施加 Yank"]
    D --> E["移除向外径向速度"]
    E --> F["纠正超长位置"]
    F --> G["沿切平面施加摆荡加速度"]
~~~

## 3. 冲量计算

冲量系统主要覆盖三类来源：

1. 枪械投射物冲量。
2. 爆炸冲量。
3. PhysX 碰撞冲量。

冲量定义为力在时间上的积分：

\[
\mathbf J=\int\mathbf F\,dt
\]

它造成动量变化：

\[
\mathbf J=\Delta\mathbf p
\]

如果质量不变：

\[
\Delta\mathbf v=\frac{\mathbf J}{m}
\]

### 3.1 枪械投射物

枪械投射物命中宝物时，按投射物动量计算冲量：

\[
\mathbf J
=
m_p\mathbf v_p k_J
\]

其中：

- \(m_p\)：投射物质量。
- \(\mathbf v_p\)：命中瞬间速度。
- \(k_J\)：冲量倍率。

实现位于 [BallisticProjectile.cs](../../Game/Runtime/Gameplay/BallisticProjectile.cs)。

冲量通过命中点施加，因此同时产生：

#### 线动量变化

\[
\Delta\mathbf v=\frac{\mathbf J}{m}
\]

#### 角动量变化

设质心到命中点的向量：

\[
\mathbf r=\mathbf p_{\mathrm{hit}}-\mathbf x_{\mathrm{COM}}
\]

角冲量：

\[
\Delta\mathbf L=\mathbf r\times\mathbf J
\]

所以子弹打在物体边缘比打在质心附近更容易使其旋转。

### 3.2 爆炸冲量

爆炸冲量随距离线性衰减。

爆心为 \(\mathbf c\)，刚体质心为 \(\mathbf x\)，距离：

\[
d=\|\mathbf x-\mathbf c\|
\]

作用半径为 \(R\)，最大冲量为 \(J_{\max}\)：

\[
J(d)
=
J_{\max}
\left(
1-\operatorname{clamp}
\left(
\frac dR,0,1
\right)
\right)
\]

为了让物体向上飞，项目将方向计算所用的表观爆心向下移动：

\[
\mathbf c'
=
\mathbf c-u\mathbf{\hat y}
\]

方向：

\[
\hat{\mathbf d}
=
\frac{\mathbf x-\mathbf c'}
{\|\mathbf x-\mathbf c'\|}
\]

最终冲量：

\[
\mathbf J=J(d)\hat{\mathbf d}
\]

实现位于 [BombProjectile.cs](../../Game/Runtime/Gameplay/BombProjectile.cs)。

爆炸对不同质量物体产生：

\[
\Delta\mathbf v=\frac{\mathbf J}{m}
\]

因此相同距离下，轻物体速度变化更大。

#### 玩家例外

玩家由 CharacterController 驱动，没有普通动态 Rigidbody。当前爆炸逻辑只对 attachedRigidbody 调用 AddForce，也没有把爆炸冲量注入玩家的外部速度。

所以当前行为是：

- 宝物、怪物、动态体素块：会被炸飞。
- 玩家：不会按同一套刚体冲量被炸飞。

### 3.3 碰撞冲量

PhysX 完成碰撞求解后，会提供：

\[
\mathbf J_{\mathrm{collision}}
\]

项目读取其大小：

\[
J=\|\mathbf J_{\mathrm{collision}}\|
\]

而不是只读取碰撞前相对速度。这样摩擦、质量、接触约束等已经包含在物理解算结果中。

### 3.4 冲量转伤害

为了让不同质量的对象共享同一伤害规则，先计算质量归一化冲量：

\[
j=\frac Jm
\]

其量纲接近速度变化：

\[
j\approx\|\Delta\mathbf v\|
\]

扣除最低伤害阈值：

\[
q=\max(0,j-j_0)
\]

最终伤害：

\[
D=
D_{\max}
\cdot f
\cdot k
\cdot q^2
\]

其中：

- \(D_{\max}\)：最大生命或初始价值。
- \(f\)：易碎度，范围 \([0,1]\)。
- \(k\)：伤害倍率，默认 0.03。
- \(j_0\)：最低比冲量阈值，默认 1。

代码位于 [CollisionImpulseDamage.cs](../../Game/Runtime/Gameplay/CollisionImpulseDamage.cs)。

平方项会形成明显的非线性：

- 小碰撞低于阈值：无伤害。
- 刚过阈值：轻微伤害。
- 高速撞击：伤害迅速增加。

### 3.5 冲量系统流程

~~~mermaid
flowchart TD
    A["枪击 / 爆炸 / PhysX 碰撞"] --> B["得到冲量 J"]
    B --> C["对 Rigidbody: Δv = J/m"]
    B --> D["对易碎物: j = J/m"]
    D --> E["扣除伤害阈值"]
    E --> F["按平方关系计算伤害"]
    F --> G["生命/价值归零"]
    G --> H["生成独立 Rigidbody 碎片"]
~~~

## 4. 地形支撑

正式地形支撑入口是 [VoxelIntegrityWorldBridge.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegrityWorldBridge.cs)。

这个系统解决的问题是：

> 当玩家挖掉一批体素后，附近剩余体素是否还通过实体路径连接到支撑点？

它不是连续力学或有限元分析，而是离散拓扑支撑模型。

### 4.1 支撑系统的数据状态

每个坐标被分类为：

- Air：空气，不参与搜索。
- Solid：普通实体。
- StructuralSupport：结构锚点。
- Unloaded：尚未加载的世界区域。

实体仍然使用：

\[
\rho\ge\rho_{\mathrm{iso}}
\land
T\neq Air
\]

VoxelTypeDefinition.IsStructuralSupport 决定某种体素是否可以作为锚点。Bedrock 通常属于这一类。

### 4.2 六连通结构图

每个实体体素是图中的一个节点。

只建立六面邻接：

\[
N(v)=
\{
v\pm(1,0,0),
v\pm(0,1,0),
v\pm(0,0,1)
\}
\]

因此：

- 共面接触：算连接。
- 只有棱接触：不算连接。
- 只有角接触：不算连接。

结构稳定条件可写成：

\[
\operatorname{Stable}(v)
\iff
\exists\text{ 六连通实体路径，从 }v\text{ 到达支撑点}
\]

### 4.3 破坏捕获

一次采矿或爆炸期间，Bridge 监听所有体素变化。

只有满足以下条件的坐标会进入完整性分析：

\[
\operatorname{Solid}(v_{\mathrm{before}})
\land
\neg\operatorname{Solid}(v_{\mathrm{after}})
\]

即“原来是实体，现在变成空气”。

系统从每个被移除体素的六邻域中寻找仍为实体的节点，作为搜索种子。

### 4.4 A* 支撑搜索

搜索优先级：

\[
f(n)=g(n)+h(n)
\]

其中：

- \(g(n)\)：从种子到节点 \(n\) 的六邻域距离。
- \(h(n)\)：节点到当前已加载体素区域最近边界面的估计距离。

使用 \(h\) 的目的不是改变最终连通性结论，而是让搜索优先接近流送边界，从而更快确认大型结构仍与外部世界相连。

### 4.5 何时判定为稳定

搜索到以下任一条件时，整个连通块按稳定处理：

#### 到达结构锚点

\[
T(v)\in\text{StructuralSupportTypes}
\]

#### 到达未加载边界

这表示该结构可能继续连接到尚未加载的世界，因此采取保守策略，不让它坍塌。

#### 达到搜索上限

默认最多访问 16384 个体素。达到上限也视为受支撑，避免大型地形因为性能保护机制而被误判成悬空。

#### 搜索耗尽

如果所有可达实体都检查完，仍未遇到任何支撑：

\[
\operatorname{Support}(C)=\varnothing
\]

则连通块 \(C\) 被判定为失稳。

搜索实现在 [VoxelIntegritySearch.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegritySearch.cs)。

### 4.6 静态体素转动态刚体

失稳连通块不会直接消失，而是：

1. 保存原始密度和类型。
2. 从静态体素世界移除。
3. 后台对连通块重新运行 Marching Cubes。
4. 计算体积、质心和质量。
5. 对表面 Mesh 做凸分解。
6. 创建动态 Rigidbody。

#### 体积

每个表面三角形与原点构成有向四面体：

\[
V_i=
\frac{
\mathbf a\cdot(\mathbf b\times\mathbf c)
}{6}
\]

总体积：

\[
V=\left|\sum_iV_i\right|
\]

#### 质心

\[
\mathbf C=
\frac{
\sum_i
V_i
\frac{\mathbf a_i+\mathbf b_i+\mathbf c_i}{4}
}{
\sum_iV_i
}
\]

#### 等价完整体素数

设体素边长为 \(l\)：

\[
N_{\mathrm{equiv}}
=
\frac{V}{l^3}
\]

考虑缩放时还会乘：

\[
|s_xs_ys_z|
\]

#### 质量

不同体素类型的平均单位质量：

\[
\bar m_v=
\frac1N\sum_i m(T_i)
\]

动态块总质量：

\[
m=
\max(0.01,N_{\mathrm{equiv}}\bar m_v)
\]

因此只占部分体积的 Marching Cubes 岩块不会按完整方块数量简单计算质量。

### 4.7 为什么需要凸分解

静态地形可以使用非凸 MeshCollider，但动态 Rigidbody 不能可靠使用非凸 MeshCollider。

因此失稳体素块需要被拆成若干凸 Collider：

    失稳体素
      → Marching Cubes 表面
      → 凸分解
      → 多个 convex MeshCollider
      → 一个复合 Rigidbody

当前最多生成 8 个凸 Collider。

### 4.8 动态体素继续碎裂

动态体素块仍然可以被采矿和爆炸。

如果一个刚体被挖成多个六连通分量，每个分量都会变成独立 Rigidbody。

新分量继承其质心位置处的父刚体速度：

\[
\mathbf v_i
=
\mathbf v_{\mathrm{parent}}
+
\boldsymbol\omega
\times
(\mathbf r_i-\mathbf r_{\mathrm{parent}})
\]

并继承角速度：

\[
\boldsymbol\omega_i=\boldsymbol\omega
\]

所以旋转中的岩块裂开时，各碎块会得到不同的线速度，保持原来的旋转运动趋势。

### 4.9 地形支撑完整流程

~~~mermaid
flowchart TD
    A["采矿/爆炸移除体素"] --> B["记录实体→空气变化"]
    B --> C["收集六邻域实体种子"]
    C --> D["A* 六连通搜索"]
    D --> E{"到达支撑、流送边界或搜索上限？"}
    E -->|"是"| F["保留静态地形"]
    E -->|"否，搜索耗尽"| G["判定失稳连通块"]
    G --> H["从静态世界移除"]
    H --> I["后台构建独立 MC Mesh"]
    I --> J["体积/质心/质量计算"]
    J --> K["凸分解"]
    K --> L["创建动态 Rigidbody"]
    L --> M["继续碰撞、爆炸或再次碎裂"]
~~~

## 四类交互的最终区分

- **磁力牵引**：用带阻尼的力改变物体运动。
- **绳索**：通过距离约束删除非法的径向运动。
- **冲量计算**：处理瞬时动量传递，并将比冲量转换成伤害。
- **地形支撑**：先用离散连通图判断是否脱落，脱落后才进入连续刚体物理。
