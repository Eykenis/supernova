# 项目物理系统详解

下面聚焦正式关卡运行时，尤其是 DenseJigsawRegion 使用的体素世界。项目中的物理由两套系统共同组成：

- **连续物理层**：Unity/团结引擎 PhysX，负责 Rigidbody、重力、接触、摩擦、冲量和 Collider。
- **离散体素层**：负责实体判定、耐久度、爆炸传播、结构支撑和坍塌判定。
- 两者的交界点是：**稳定体素形成静态 MeshCollider；失稳体素被移出世界并转换成动态 Rigidbody。**

~~~mermaid
flowchart TD
    A["密度场与体素类型"] --> B["Marching Cubes 表面"]
    B --> C["静态非凸 MeshCollider"]
    C --> D["玩家、怪物、道具发生碰撞"]

    E["采矿 / 爆炸"] --> F["体素变为空气"]
    F --> G["结构完整性搜索"]
    G -->|"仍连接支撑"| H["保留为静态地形"]
    G -->|"完全失去支撑"| I["提取体素连通块"]
    I --> J["重建 Mesh + 凸分解"]
    J --> K["动态 Rigidbody"]
    K --> D
    K --> L["继续采矿后再次拆分"]
~~~

## 1. 全局物理配置

项目物理配置位于 [DynamicsManager.asset](../../../ProjectSettings/DynamicsManager.asset)：

- 全局重力：

\[
\mathbf g=(0,-9.81,0)\ \mathrm{m/s^2}
\]

- 固定物理步长：

\[
\Delta t_{\text{fixed}}=0.02\ \mathrm{s}
\]

即理想情况下每秒进行 50 次物理解算。

- 默认位置求解迭代：6。
- 默认速度求解迭代：1。
- Auto Sync Transforms 关闭。
- 默认所有 Layer 互相碰撞，但代码会针对玩家投射物、生物群体等调用 Physics.IgnoreCollision。
- 静止阈值为 0.005，默认接触偏移为 0.01m。

洞穴地形使用 [CaveTerrain.physicMaterial](../../Game/Materials/Physics/CaveTerrain.physicMaterial)：

- 动摩擦系数：0.8。
- 静摩擦系数：0.9。
- 弹性：0。

所以洞穴表面整体表现为“高摩擦、不弹跳”。

## 2. 体素如何变成物理地形

### 2.1 实体判定

体素样本首先按密度和类型判断是否为实体：

\[
\operatorname{Solid}(v)=
(\rho_v\ge \rho_{\mathrm{iso}})
\land
(T_v\neq Air)
\]

当前正式配置的等值面：

\[
\rho_{\mathrm{iso}}=0
\]

负密度是空气，非负密度且类型非 Air 才参与地形构建。

### 2.2 碰撞面不是方块表面

项目用 Marching Cubes 从标量密度场提取表面。对于一条横跨等值面的边，两个端点为 \(\mathbf p_a,\mathbf p_b\)，密度为 \(\rho_a,\rho_b\)，交点插值参数为：

\[
t=
\operatorname{clamp}
\left(
\frac{\rho_{\mathrm{iso}}-\rho_a}
{\rho_b-\rho_a},
0,1
\right)
\]

顶点位置为：

\[
\mathbf p=
\mathbf p_a+t(\mathbf p_b-\mathbf p_a)
\]

实现位于 [MarchingCubesMesher.cs](../../Game/Runtime/Voxels/MarchingCubesMesher.cs)。

因此 PhysX 最终接触到的是平滑三角形洞穴表面，而不是离散方块盒子。

### 2.3 静态 MeshCollider

每个 32³ Mesh Section 构建完成后：

1. 先提交渲染 Mesh。
2. 延迟到后处理阶段更新 MeshCollider。
3. 使用同一份 Marching Cubes Mesh 作为碰撞形状。
4. 地形对象没有 Rigidbody，所以可以使用非凸 MeshCollider。

相关提交代码在 [MinecraftCaveInfiniteWorld.cs](../../Game/Runtime/MinecraftCaveInfiniteWorld.cs)。

这里还使用了碰撞 Mesh 双缓冲：

- 新渲染 Mesh 上传后，旧 Collider Mesh 暂时继续有效。
- 新 Collider 完成提交后才释放旧 Mesh。
- 避免体素被采掉后，Collider 在某一帧短暂消失，使玩家或掉落物穿过地面。

由于全局自动同步 Transform 被关闭，项目会在需要时显式调用 Physics.SyncTransforms。

## 3. 玩家：运动学角色，不是 Rigidbody

玩家由 [VoxelPlayerController.cs](../../Game/Runtime/Voxels/VoxelPlayerController.cs) 中的 CharacterControllerMotor 驱动。

玩家没有参与刚体质量、受力和接触冲量求解，而是每帧计算位移，然后调用 CharacterController.Move。

### 3.1 基本速度

玩家总速度被拆成：

\[
\mathbf v=
s\mathbf d+
v_y\mathbf{\hat y}+
\mathbf v_{\mathrm{ext}}
\]

其中：

- \(s\)：行走速度。
- \(\mathbf d\)：输入方向，长度最大为 1。
- \(v_y\)：项目自行积分的竖直速度。
- \(\mathbf v_{\mathrm{ext}}\)：绳索、拉拽等机制注入的额外速度。

每帧位移：

\[
\Delta\mathbf x=\mathbf v\Delta t
\]

序列化默认参数位于 [PlayerProfile.cs](../../Game/Runtime/Gameplay/PlayerProfile.cs)：

- 行走速度 \(s=4m/s\)。
- 蹲伏速度 \(2m/s\)。
- 跳跃高度 \(h=1.1m\)。
- 玩家自定义重力 \(g_p=20m/s^2\)。
- 贴地向下速度 \(2m/s\)。

注意玩家使用的 20m/s² 与 PhysX 全局的 9.81m/s² 不同，所以玩家下落明显快于普通 Rigidbody。

### 3.2 重力和跳跃

空中使用显式欧拉积分：

\[
v_y^{n+1}=v_y^n-g_p\Delta t
\]

跳跃初速度由目标高度反推：

\[
v_{\mathrm{jump}}=\sqrt{2g_ph}
\]

代入默认值：

\[
v_{\mathrm{jump}}
=\sqrt{2\times20\times1.1}
\approx6.63m/s
\]

在理想连续情况下，最高点满足：

\[
h=\frac{v_{\mathrm{jump}}^2}{2g_p}=1.1m
\]

落地时不把竖直速度设为零，而是设为：

\[
v_y=-2m/s
\]

这样角色胶囊会持续轻压地面，减少斜坡和浮点误差造成的 isGrounded 抖动。

### 3.3 墙面动量吸收

如果 CharacterController 实际位移小于期望位移：

\[
\mathbf b=
\Delta\mathbf x_{\mathrm{intended}}
-
\Delta\mathbf x_{\mathrm{actual}}
\]

取水平方向单位向量：

\[
\hat{\mathbf b}
=\frac{\mathbf b_{xz}}{\|\mathbf b_{xz}\|}
\]

进入墙面的外部速度分量为：

\[
v_{\mathrm{in}}
=\mathbf v_{\mathrm{ext}}\cdot\hat{\mathbf b}
\]

当 \(v_{\mathrm{in}}>0\) 时，移除其中 90%：

\[
\mathbf v_{\mathrm{ext}}'
=
\mathbf v_{\mathrm{ext}}
-
0.9v_{\mathrm{in}}\hat{\mathbf b}
\]

因此撞墙后，朝墙方向的动量大幅消失，而切向速度仍然保留，玩家会沿墙滑动而不是完全停住。

### 3.4 外部速度衰减

外部动量每帧按线性阻尼衰减：

\[
\mathbf v_{\mathrm{ext}}'
=
\mathbf v_{\mathrm{ext}}
\operatorname{clamp}(1-k\Delta t,0,1)
\]

其中：

- 地面 \(k=8\)。
- 空中 \(k=0.35\)。

所以地面很快吸收绳索释放后的横向动量，空中则保留较长时间。

## 4. 绳索：单边距离约束

绳索数学集中在 [RopeConstraint.cs](../../Game/Runtime/Gameplay/RopeConstraint.cs)。

它不是弹簧，也不是持续向锚点施力，而是一个单边约束：

\[
\|\mathbf x-\mathbf a\|\le L
\]

其中：

- \(\mathbf x\)：玩家连接点。
- \(\mathbf a\)：飞镐锚点。
- \(L\)：当前绳长。

### 4.1 消除向外速度

设：

\[
\mathbf r=\mathbf x-\mathbf a,\qquad
\mathbf n=\frac{\mathbf r}{\|\mathbf r\|}
\]

径向速度为：

\[
v_r=\mathbf v\cdot\mathbf n
\]

当绳索已拉紧且 \(v_r>0\) 时：

\[
\mathbf v'
=
\mathbf v-v_r\mathbf n
\]

也就是只消除向外拉长绳子的速度，保留切向速度：

\[
\mathbf v_t
=
\mathbf v-(\mathbf v\cdot\mathbf n)\mathbf n
\]

这个切向分量就是摆荡产生的基础。

### 4.2 位置纠正

单纯修正速度仍会让重力在每帧泄漏一小段位移，因此当距离超过绳长时，还要应用位置修正：

\[
\Delta\mathbf x
=
\mathbf r
\left(
\frac{L}{\|\mathbf r\|}-1
\right)
\]

修正后：

\[
\|\mathbf r+\Delta\mathbf x\|=L
\]

这用于避免绳索逐帧“变长”和满绳状态下的竖直抖动。

### 4.3 摆荡输入

玩家输入 \(\mathbf d\) 首先投影到绳索球面的切平面：

\[
\mathbf d_t
=
\mathbf d-(\mathbf d\cdot\mathbf n)\mathbf n
\]

摆荡加速度：

\[
\mathbf a_{\mathrm{swing}}
=
a_s\frac{\mathbf d_t}{\|\mathbf d_t\|}
\]

朝锚点或背离锚点的输入会被消掉，只有沿摆动圆弧的输入才能“荡高”。

### 4.4 收绳和瞬时拉扯

收绳：

\[
L'=
\operatorname{clamp}
(L-u\,s_r\Delta t,L_{\min},L_{\max})
\]

第一次绷紧时还会施加一次朝内速度变化：

\[
\Delta\mathbf v_{\mathrm{yank}}
=
-\mathbf n\,
\min(v_rk_y,v_{\max})
\]

这使绳子突然绷紧时表现为一次“猛拽”，而不是平缓的吸引力。

## 5. 磁力：带限幅的 PD 弹簧

普通磁吸作用于真正的 Rigidbody，实现在 [FirstPersonMagnetInteractor.cs](../../Game/Runtime/Gameplay/FirstPersonMagnetInteractor.cs)。

位置误差：

\[
\mathbf e=\mathbf x_{\mathrm{target}}-\mathbf x_{\mathrm{body}}
\]

相对速度：

\[
\mathbf v_r=
\mathbf v_{\mathrm{player}}
-
\mathbf v_{\mathrm{body}}
\]

磁力采用 PD 形式：

\[
\mathbf F=
k_p\mathbf e+c\mathbf v_r
\]

默认参数：

- \(k_p=300\)。
- \(c=90\)。
- 最大吸引力 \(F_{\max}=800N\)。
- 最大加速度 \(a_{\max}=40m/s^2\)。

最终还要满足：

\[
\|\mathbf F\|
\le
\min(F_{\max},ma_{\max})
\]

第二个限制很重要：轻物体不会因为质量过小而获得极高加速度。

### 抬升衰减

物体相对拾取高度的抬升量为：

\[
\Delta h=\max(0,h-h_0)
\]

最大向上力：

\[
F_{\mathrm{lift,max}}
=
\frac{F_{\mathrm{lift},0}}
{1+\alpha\Delta h}
\]

抬得越高，允许的向上力越弱。

### 朝向控制

旋转同样是 PD 控制：

\[
\boldsymbol\tau
=
k_R\theta\hat{\mathbf a}
-
c_R\boldsymbol\omega
\]

其中 \(\theta\hat{\mathbf a}\) 来自目标四元数与当前四元数的误差。扭矩最后按最大值限幅。

## 6. 喷气背包

喷气背包并不通过 AddForce 模拟推力，而是接管 CharacterController 位移。

悬停速度为：

\[
\mathbf v=
s\mathbf d+
(v_{\mathrm{up}}-v_{\mathrm{down}})\mathbf{\hat y}
\]

启动阶段额外高度采用 SmoothStep：

\[
u=\operatorname{clamp}\left(\frac{t}{T},0,1\right)
\]

\[
S(u)=3u^2-2u^3
\]

\[
h(t)=h_0S(u)
\]

每帧只应用高度差：

\[
\Delta h=h(t+\Delta t)-h(t)
\]

实现位于 [JetpackEquipmentInteraction.cs](../../Game/Runtime/Gameplay/JetpackEquipmentInteraction.cs)。

因此喷气背包是“规定速度和位移”的运动学能力，而不是按质量计算真实升力。

## 7. 怪物：Rigidbody 运动控制

怪物使用 [CreaturePhysicsMotor.cs](../../Game/Runtime/Creatures/CreaturePhysicsMotor.cs)，属于动态刚体。

它保留 PhysX 对竖直方向的重力和碰撞响应，只主动控制水平速度。

将刚体速度分解为：

\[
v_y=\mathbf v\cdot\mathbf u
\]

\[
\mathbf v_h=\mathbf v-v_y\mathbf u
\]

目标水平速度：

\[
\mathbf v_d=s_d\hat{\mathbf d}
\]

每个 FixedUpdate：

\[
\mathbf v_h'
=
\operatorname{MoveTowards}
(\mathbf v_h,\mathbf v_d,a\Delta t)
\]

最后：

\[
\mathbf v'
=
\mathbf v_h'+v_y\mathbf u
\]

这不是施力，而是直接引导水平速度；竖直速度仍由重力和接触求解器负责。

### 怪物跳跃

怪物读取全局重力：

\[
v_{\mathrm{jump}}
=
k_j\sqrt{2gh}
\]

默认修正系数：

\[
k_j=1.15
\]

这个额外 15% 用来补偿导航使用整数体素层，而实际脚底接触的是 Marching Cubes 插值表面。

### 地面判定

接触法线 \(\mathbf n\) 满足：

\[
\mathbf n\cdot\mathbf u
\ge
\cos\theta_{\max}
\]

才被视为地面。默认：

\[
\theta_{\max}=55^\circ
\]

另外保留 0.1s 的土狼时间，吸收斜坡接触偶尔丢失一帧的问题。

怪物自身 Collider 会被换成零摩擦材质，防止高摩擦洞穴表面抵消代码写入的水平速度。

## 8. 投射物、冲量和爆炸

### 8.1 枪械投射物

[BallisticProjectile.cs](../../Game/Runtime/Gameplay/BallisticProjectile.cs) 使用动态刚体和连续碰撞检测，但明确关闭重力。

所以飞行近似：

\[
\mathbf x(t)=\mathbf x_0+\mathbf v_0t
\]

它在首次碰撞后销毁，不存在弹道下坠。

命中宝物时传递的冲量：

\[
\mathbf J
=
m_p\mathbf v_{\mathrm{impact}}k_J
\]

然后通过 AddForceAtPosition 作用在命中点，所以除了线速度变化：

\[
\Delta\mathbf v=\frac{\mathbf J}{m}
\]

还会产生角冲量：

\[
\Delta\mathbf L
=
(\mathbf p_{\mathrm{hit}}-\mathbf x_{\mathrm{COM}})
\times\mathbf J
\]

### 8.2 投掷物

炸弹等投掷物初速度通常是：

\[
\mathbf v_0
=
s_f\mathbf f+s_u\mathbf{\hat y}
\]

初始角速度：

\[
\boldsymbol\omega_0=s_\omega\hat{\mathbf r}
\]

若其 Rigidbody 启用重力，忽略空气阻力时：

\[
\mathbf x(t)
=
\mathbf x_0+\mathbf v_0t+\frac12\mathbf gt^2
\]

### 8.3 爆炸对 Rigidbody 的冲量

爆炸在球形范围内查找 Collider。距离爆心 \(d\) 的冲量大小线性衰减：

\[
J(d)
=
J_{\max}
\left(
1-\operatorname{clamp}\frac dR
\right)
\]

为了给爆炸增加向上分量，方向不是从真实爆心计算，而是从向下偏移后的“表观爆心”计算：

\[
\mathbf c'
=
\mathbf c-u\mathbf{\hat y}
\]

\[
\hat{\mathbf d}
=
\frac{\mathbf x_{\mathrm{body}}-\mathbf c'}
{\|\mathbf x_{\mathrm{body}}-\mathbf c'\|}
\]

\[
\mathbf J=J(d)\hat{\mathbf d}
\]

实现位于 [BombProjectile.cs](../../Game/Runtime/Gameplay/BombProjectile.cs)。

由于使用 ForceMode.Impulse：

\[
\Delta\mathbf v=\frac{\mathbf J}{m}
\]

同一爆炸下，轻物体比重物体飞得更快。

当前玩家是 CharacterController，不是附带 Rigidbody 的对象；现有爆炸调用链也没有把这份冲量转交给玩家的 externalVelocity。因此玩家不会像宝物或怪物那样直接被爆炸刚体冲量炸飞。

## 9. 碰撞冲量如何转成伤害

项目没有简单使用相对速度，而是读取 PhysX 已求解的接触冲量：

\[
J=\|\mathbf J_{\mathrm{collision}}\|
\]

然后除以接收者质量：

\[
j=\frac Jm
\]

这个“比冲量”近似物体速度变化 \(\Delta v\)，使不同质量的对象可以使用同一套易碎阈值。

扣除阈值：

\[
q=\max(0,j-j_0)
\]

最终伤害或价值损失：

\[
D=
D_{\max}\,
f\,
k\,
q^2
\]

其中：

- \(D_{\max}\)：最大生命或初始价值。
- \(f\in[0,1]\)：易碎度。
- \(k\)：每单位平方比冲量对应的百分比。
- 默认 \(j_0=1\)。
- 默认 \(k=0.03\)。

实现位于 [CollisionImpulseDamage.cs](../../Game/Runtime/Gameplay/CollisionImpulseDamage.cs)。

平方项意味着冲量刚过阈值时伤害较轻，但高速撞击会迅速放大。宝物最终按 CeilToInt 转成整数价值损失。

碰撞烟尘使用另一套较低阈值，只负责视觉反馈，不直接决定伤害。相关逻辑位于 [RigidbodyImpactFeedback.cs](../../Game/Runtime/Effects/RigidbodyImpactFeedback.cs)。

## 10. 爆炸对体素的破坏不是连续冲击波

体素爆炸使用离散球形采样和分段伤害：

\[
P(d)=
\begin{cases}
P_{\mathrm{inner}},&0\le d\le R_{\mathrm{inner}}\\
P_{\mathrm{outer}},&R_{\mathrm{inner}}<d\le R\\
0,&d>R
\end{cases}
\]

默认炸弹参数定义在 [VoxelExplosion.cs](../../Game/Runtime/Voxels/VoxelExplosion.cs)：

- 半径 \(R=2m\)。
- 内半径 \(1m\)。
- 内层破坏力 30。
- 外层破坏力 10。
- 传播除数 2。

当体素被摧毁后，超出其耐久度的剩余伤害继续传播：

\[
P_{\mathrm{next}}
=
\frac{P_{\mathrm{excess}}}
{k_{\mathrm{propagation}}}
\]

传播只进入同类型的 26 邻域体素，并保留到达某个体素的最强伤害路径。

所以这里模拟的是“可控制的游戏性爆破”，不是压力波、材料应力或流体动力学。

## 11. 正式体素完整性系统

正式入口是 [VoxelIntegrityWorldBridge.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegrityWorldBridge.cs)。

它包裹 IVoxelTerrain：

1. 监听一次采矿或爆炸期间发生的体素变化。
2. 记录所有从实体变成空气的坐标。
3. 从这些空洞的六邻域开始做结构搜索。
4. 找到失去全部支撑的实体连通块。
5. 将失稳块从静态地形移除。
6. 后台构建动态体素刚体。

### 11.1 支撑图

每个实体体素是一个节点，只建立六面邻接边：

\[
E=
\{(u,v)\mid \|u-v\|_1=1\}
\]

也就是只认上下左右前后，不认斜角接触。

### 11.2 A* 搜索

搜索优先级为：

\[
f(n)=g(n)+h(n)
\]

其中：

- \(g(n)\)：从受影响种子到当前体素的六邻域路径长度。
- \(h(n)\)：到当前已加载体素区域六个边界面的最短估计距离。

实现位于 [VoxelIntegritySearch.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegritySearch.cs)。

连通块遇到以下任一条件就按“仍受支撑”处理：

- 到达标记为 StructuralSupport 的体素，例如 Bedrock。
- 到达尚未加载的流送边界。
- 搜索达到最大体素数，默认 16384。

把未加载边界和搜索上限视为支撑，是保守策略：系统宁可暂时不塌，也不会因为流送范围有限而把整片世界误判成悬空。

只有当搜索完整耗尽，而且没有遇到任何支撑时，连通块才会坍塌。

因此这不是有限元应力计算；正式系统中的“稳定”定义本质上是：

\[
\text{Stable}
\iff
\text{存在六连通路径通向支撑或保守边界}
\]

## 12. 失稳体素如何变成动态刚体

失稳连通块首先重新运行一次 Marching Cubes，生成独立封闭表面，见 [DynamicVoxelBodyBuilder.cs](../../Game/Runtime/Voxels/Integrity/DynamicVoxelBodyBuilder.cs)。

### 12.1 网格体积和质心

对于三角形 \((\mathbf a,\mathbf b,\mathbf c)\)，与原点构成的有向四面体体积：

\[
V_i=
\frac{
\mathbf a\cdot(\mathbf b\times\mathbf c)
}{6}
\]

总有向体积：

\[
V_s=\sum_i V_i
\]

每个四面体的质心：

\[
\mathbf c_i=
\frac{\mathbf a+\mathbf b+\mathbf c}{4}
\]

整体质心：

\[
\mathbf C=
\frac{
\sum_i V_i\mathbf c_i
}{
V_s
}
\]

实际体积：

\[
V=|V_s|
\]

代码位于 [VoxelIntegrityRigidbodyFactory.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegrityRigidbodyFactory.cs)。

### 12.2 质量

先把 Mesh 体积换算成“等价完整体素数”：

\[
N_{\mathrm{equiv}}
=
\frac{
V\,|s_xs_ys_z|
}{
l_{\mathrm{voxel}}^3
}
\]

不同体素类型的质量参数取平均：

\[
\bar m_v=
\frac1N\sum_{i=1}^{N}m(T_i)
\]

刚体质量：

\[
m=
\max(0.01,N_{\mathrm{equiv}}\bar m_v)
\]

所以 Marching Cubes 只形成半个体素体积时，质量也会相应减少，而不是简单使用“体素数量 × 固定质量”。

代码只显式计算了体积、质心和总质量；惯性张量仍主要由 PhysX 根据凸 Collider 组合计算。

### 12.3 凸碰撞体

动态 Rigidbody 不能使用一个非凸 MeshCollider。因此项目使用凸分解，把不规则洞穴碎块变成少量凸 MeshCollider 的复合体：

- 默认凹度阈值：0.1。
- 每个刚体最多 8 个凸 Collider。
- 使用连续动态碰撞检测。
- 使用 Rigidbody 插值。

创建代码位于 [VoxelIntegrityRigidbodyFactory.cs](../../Game/Runtime/Voxels/Integrity/VoxelIntegrityRigidbodyFactory.cs)。

如果异步构建没有生成封闭表面，系统不会留下消失的地形，而是把捕获到的体素恢复回静态世界。

## 13. 动态体素继续破坏和拆分

动态体素块内部仍保存原始体素坐标和类型，因此玩家可以继续挖它。

破坏后重新做六连通分量搜索。若原刚体裂成多个部分，每个部分都会获得自己的 Mesh、Collider 和 Rigidbody。

拆分时，新块速度不是简单复制父刚体线速度，而是取新质心处的点速度：

\[
\mathbf v_i
=
\mathbf v_{\mathrm{COM}}
+
\boldsymbol\omega
\times
(\mathbf r_i-\mathbf r_{\mathrm{COM}})
\]

角速度保持：

\[
\boldsymbol\omega_i=\boldsymbol\omega
\]

这由 Rigidbody.GetPointVelocity 实现，见 [DynamicVoxelBody.cs](../../Game/Runtime/Voxels/Integrity/DynamicVoxelBody.cs)。

因此正在旋转的岩块被挖成两半后，两半不会获得完全相同的线速度，而会继承各自在原旋转刚体上的局部运动。

## 14. 流送与物理同步

世界流送期间，动态对象可能正处于即将卸载或重建的柱内。项目对此做了显式保护：

1. 记录 Rigidbody 的线速度和角速度。
2. 临时停用对象。
3. 更新地形 Mesh 和 Collider。
4. 调用 Physics.SyncTransforms。
5. 恢复对象和原速度。
6. WakeUp 重新进入解算。

矿物掉落也会在对应地形 Collider 重建完成前临时变成 Kinematic，并关闭碰撞，见 [MinedOreDrop.cs](../../Game/Runtime/Voxels/MinedOreDrop.cs)。

这避免刚挖出的矿物在旧 Collider 尚未删除时被弹飞，或者在新 Collider 尚未建立时穿过洞穴。

初始加载阶段还会暂时执行：

\[
\mathbf g=\mathbf 0
\]

等所需地形 Collider 就绪后再恢复原重力，见 [MinecraftCaveInfiniteWorld.cs](../../Game/Runtime/MinecraftCaveInfiniteWorld.cs)。

## 15. 射线检测结构

体素交互不是只信任 Collider 命中的 GameObject。

[VoxelTargetResolver.cs](../../Game/Runtime/Voxels/VoxelTargetResolver.cs) 使用两阶段检测：

1. Physics.RaycastAll 提供宽阶段候选。
2. 静态地形根据命中点反查附近实体体素。
3. 动态体素块使用其 Marching Cubes 三角形 BVH 做精确射线检测。
4. 比较静态和动态命中距离，选择最近表面。

这样即使一个动态体素块由多个近似凸 Collider 组成，准星选中的仍是实际可见的 Marching Cubes 三角面，而不是粗略凸包表面。

## 16. 原型支撑系统与正式系统的区别

项目中还保留了一套 Voxels/Support/Prototype 原型。它使用双向 BFS 和近似 EBC-LB 最短支撑路径模型：

\[
L(v)=d_{\mathrm{source}}(v)+d_{\mathrm{anchor}}(v)
\]

最短基线：

\[
L_{\min}=\min_v L(v)
\]

若体素无法同时从载荷源和支撑锚点到达，或：

\[
L(v)>L_{\min}
+
\max\left(1,\frac{L_{\min}}2\right)
\]

则被视为不在有效受力路径上。

这套实现位于 [VoxelSupportGraph.cs](../../Game/Runtime/Voxels/Support/Prototype/VoxelSupportGraph.cs)，主要用于支撑实验场景；正式 Dense Jigsaw 链路使用的是前述 VoxelIntegrityWorldBridge + VoxelIntegritySearch。

总体上，当前项目并不是“完全真实物理模拟”，而是把不同需求分层处理：

- 地形形状和碰撞：Marching Cubes + PhysX。
- 玩家：可控的运动学模型。
- 生物和道具：动态刚体。
- 磁力和绳索：自定义约束、弹簧和阻尼。
- 爆炸：体素离散破坏与刚体连续冲量并行。
- 坍塌：离散连通性决定是否脱落，脱落后再交给连续刚体物理。
